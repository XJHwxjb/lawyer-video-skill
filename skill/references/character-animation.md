# 人物动作设计与检查

当人物表演是视频主体或用户反馈人物动作不自然时使用。先以大的、清晰的人物做短样；优先解决结构和时间连续性，再追求细节。适配用户指定的风格；本技能提供的角色是可编辑、风格化二维人物，不是自然真人动画。

## 四个动作原则

- **手臂从肩出发。** 保持上臂与前臂长度合理，肩、肘、腕连接稳定；肘不要穿进躯干或突然翻到另一侧。不同姿势可分别设置可控的肘部位置，避免一个逆运动学弯曲符号用于所有姿态。先检查放松、行走、递交、指向、摸额头等姿势，再让它们平滑过渡。
- **手与道具相接。** 手掌方向顺应手腕、手指和道具；拿手机、文件、钱、放大镜时在握持位置检查前后遮挡，避免物体漂在手外或穿过脸。只做必要的指节线，防止手过大或像胶囊。
- **走路要有支撑。** 每条腿交替经历落地、承重、抬脚、向前摆动、再落地；支撑脚在地面尽量保持世界坐标稳定，避免滑步。身躯有小幅重心转移、起伏和对侧摆臂，但不要把落地脚和身体一起上下平移。观察一个完整周期和起步、停步，不要只看一张静帧。
- **表情服务情境。** 眨眼、视线、眉形、嘴型与头部朝向要适合内容，避免惊慌时微笑、两个人同步机械表演，以及手挡住眼睛。情绪与姿势渐变，避开突然变脸和关节跳变。

## 具体检验

使用最终测试 MP4，而非只看源代码。检查：静站正面和侧向、每个步态接触/离地/抬脚/落地、动作中间帧与切换前后、道具接触、眨眼、担忧和交流；同时播放视频感受节奏。可以 4–8 帧/秒连续抽帧排成图来定位问题，关键转场再加密到逐帧检查。看完后记录可复现时间点，修复并重渲染；切勿凭没有完整播放的抽帧宣称所有动作自然。

模板中 `Person` 的手肘为分姿势控制，步行支撑脚与位移相配合，人物的形象、动作和动作长度仍需按实际场景调整。样片展示的二维正面风格存在运动方向和透视表达的局限；用户需要写实或侧身走路时，应改用相应角色设计或动画工具，不能声称模板是写实的。

## 给 Agent 的逐步操作说明

本文件写给负责制作视频的 Agent。用户看重人物的手、走路、神情和动作时，先读本文件，再修改和检查人物。模板是一段**二维正面卡通**动作样片，主要验证走路、停步、担忧、交流、微笑和指向。它不是全自动动画系统，也不是写实的真人运动：换姿势、拿道具、镜头方向或人物比例后都要重新检查，不能声称所有动作都已验证。

### 第一步：找到代码，弄懂坐标

先把 `../assets/character-study/` 整个复制到单独的工作项目目录；不要直接在技能安装目录改模板。文件作用如下：

| 文件或对象 | 作用 |
| --- | --- |
| `src/index.tsx` | 安排测试片的时长、人物位置和每个时间点的动作。当前样片是 30 帧/秒，共 300 帧，即 10 秒。 |
| `src/lib/actors.tsx` 中的 `Person` | 绘制人物的身体、面部、四肢及部分手持道具。 |
| `src/lib/actors.tsx` 中的 `Hand` | 根据肘部、手腕位置画手掌，并将手掌旋转到前臂方向。 |
| `move(f, start, duration)` | 返回 0 到 1 的平滑过渡值；例如 `move(f, 30, 15)` 表示第 30 帧开始，经过 15 帧逐渐完成。 |
| `Ground` | 画人物下方的平台；它不是物理地面，脚底是否接地仍需人工检查。 |

`Person` 需要放在 `<svg>` 内。例如 `<Person x={600} y={815} s={1.85} f={f} act="walk" />` 中，`x`、`y` 是人物在整张画面上的位置，`y` 近似脚底基准；`s` 是人物整体缩放；`f` 是当前帧号；`act` 是动作名称。`kind` 可选 `woman`、`man`、`officer`，`emotion` 可选 `calm`、`sad`、`alarm`、`smile`。这些名称是代码中的固定英文值，不要替换成中文。

人物内部还使用一套**局部坐标**：人物脚底约为 `(0, 0)`；向右是 x 增大，向下是 y 增大，所以人物头部和肩部的 y 值通常是负数。比如 `[36, -177]` 表示局部坐标中右侧肩部的位置，`[43, -246]` 靠近头部。`s` 和外层 `x`、`y` 会把局部坐标缩放、移动到最终画面。`face={-1}` 会水平镜像整个角色，不只是翻转脸；镜像后要重新检查手、道具、走向与文字，特别是物体的左右关系。

人物可以由整片的全局帧驱动，也可以在某个 `Sequence` 中由局部帧驱动：局部 `f=0` 是该镜头的第一帧。**同一段动作里必须统一使用一种时间基准**，不要把全局帧和局部帧混用，否则人物会提前移动或突然跳动。

### 第二步：先摆肩、肘、腕，再画手

人手的位置由三点决定：肩部是起点，肘部负责弯折，手腕是终点。先看手臂整体，再处理手掌与指尖。模板 `Person` 的 `arm(side, hand)` 中：

1. `side=-1` 和 `side=1` 分别代表人物局部坐标的左侧和右侧；镜像之后画面左右会相反。
2. `shoulder` 是肩部；`relaxed` 是垂手时的肘部；`target` 是某个动作的目标肘部；`hand` 是手腕位置。
3. 例如 `act==='worry'` 时，右侧手腕为 `[43,-246]`，右肘目标为 `[72,-187]`：先把肘放在身体外侧，再让前臂伸向太阳穴。两点不是屏幕绝对像素，修改后要看实际渲染效果。
4. `poseWeight` 让肘和腕在放松位置与动作目标之间插值：`0` 为放松，`1` 为目标姿势。它不会自动平滑面部表情、手势切换，也不是精确的骨骼长度约束。

实际修手臂时，先暂停在动作的起点、中间、终点：肩膀不应脱离衣服；肘不要穿入躯干或突然翻到另一侧；手腕不要停在脸内部。比较上臂和前臂长度，手伸得过远时优先调整人物、道具或镜头位置，不要让胳膊无故伸长。人物后面的手可能被身体遮住，这是图层顺序的结果；如果遮挡错误，检查 `arm(-1,left)`、身体和 `arm(1,right)` 的绘制先后。

**不要只把逆运动学弯曲符号翻转。** 当前文件仍有一个 `elbow(...)` 函数，但当前 `arm` 使用 `relaxed` / `target` 明确控制肘部位置；`elbow(...)` 没有参与这个手臂的渲染。修改未调用的函数不会修复画面。我们曾经只反转方向，结果两个手肘向外撑、像双手叉腰，抬手还可能穿过脸；因此要针对每个动作检查并设置位置。`worry`、`talk`、`point` 等已有目标肘部；其他预设动作不能假定已有适合的肘部，应逐项试画。

### 第三步：让手真正拿到物体

`Hand` 根据从肘部到手腕的方向旋转，支持 `open`、`point`、`stop`、`grip`。其中 `grip` 使用基本手掌轮廓和握持线条，不等于真正的逐指抓握。`prop="phone"`、`prop="folder"`、`prop="money"` 会启用模板中的相应道具；部分 `act` 也会自动画手机或放大镜。这些是**可调整的起点，不是经过所有姿态验证的握持系统**。

例如要做“拿手机查看信息”：先让手腕到手机边缘；再移动手机组的 `translate(...)`，使掌心或指尖与机身相接；最后调整绘制顺序，让手机的一部分在手前、另一部分可以被手指遮挡。检查这三个时刻：手靠近手机、手接触手机、手拿稳手机。逐帧看过渡，避免手机漂浮、插进手掌、挡住眼睛或手从道具后突然跳到前面。转账、递交文件、拿放大镜也按相同步骤处理；不能通过更改文字冒充完成了握持动画。

人物与道具之间发生接触时，应该为接触点选择共同的坐标或明确的偏移量，并确保两者随时间一起移动；如涉及镜像、旋转或缩放，必须把坐标变换一起考虑。视频中钱或文件由一人移到另一人时，安排伸手、接触、松手、收回的先后顺序，并以口播时间为准，不凭空增加故事事实。

### 第四步：让脚先落地，再移动身体

现有 `leg(side)` 使用 48 帧一个周期，两条腿的 `phase` 相差半个周期。前半段是支撑期：脚相对身体由前向后移动；后半段是摆动期：脚抬起，向前摆回。`footLift` 只在摆动期抬脚，`bodyBob` 用于躯干和髋部的小幅起伏；不要把整个角色整体上下平移，否则落地脚也会离地。

在 30 帧/秒的样片里，支撑期约 24 帧，局部脚部位移从 `+30` 到 `-30`，即每帧约 `60 ÷ 24 = 2.5` 个**人物局部坐标单位**。`src/index.tsx` 的 `travelled` 把 `2.5 × 角色缩放 1.85` 用于人物每帧的水平位移，并通过 `walkingWeight` 降速停步。这个配合是为了让正常支撑阶段尽量少滑动，减速、动作切换和不同缩放条件仍需审片，不能承诺任何一帧都完全锁脚。

修改步幅、周期或人物速度时，把三者一起改：先确定一次支撑期脚在局部坐标中的位移，再根据支撑期帧数计算每帧速度，乘以角色缩放得到画面中的人物位移。`face={-1}` 或人物向左走时，要检查位移方向是否与脚步方向一致，必要时重新设计步态。正面卡通横移只能示意走路；用户要求清楚的侧身、转向或写实步态时，应绘制相应角度的角色或选择合适的动画工具，而不是强称这个正面模板是真实侧身行走。

让另一只手臂随步伐轻微摆动，幅度不应大到穿过躯干；多人动作适当错开，避免完全同步。检查起步、一个完整步行周期、减速和停步；只看双脚分开的静帧不能判断是否滑步。

### 第五步：让表情跟情境走

`emotion` 会影响眼睛、眉毛和嘴，`blinkCycle` 控制眨眼，`gazeX/gazeY` 控制视线，`headTilt` 控制头部倾斜。样片通过 `f` 决定何时变成担忧、交流和微笑；它展示的是表情**切换**，并不保证所有眉眼嘴型之间都是连续渐变。若切换突兀，改成在若干帧内插值或交叉淡化，检查不能出现双眼、两张嘴重叠；保持手臂过渡与表情变化各自可控。

按叙事情境选择表情：收到拒收消息可以先惊讶再低落，核对证据时可专注，解释处理方式时用平静或轻微鼓励的神情。不要让难过情境下的人物持续微笑，也不要为了“有动效”而频繁眨眼、说话时嘴不停随机开合。视线要看向另一位人物、手机或材料；头部和手移动时检查手没有覆盖眼睛。

### 第六步：样片与连续动作验收

进入复制后的模板目录，安装依赖、运行类型检查并渲染，按模板 README 的命令执行。生成的样片默认路径为 `out/character-study.mp4`。播放实际 MP4，至少看一遍全片，重点观察走路是否像前进、脚是否滑动、肘与手是否自然、动作切换是否突兀。若当前环境没有播放工具，就明确说明尚未完成动态播放检查，不能把静帧检查说成实播通过。

下列命令创建检查目录，再每秒提取 4 张图片；它们是辅助检查，不能代替连续播放：

```bash
node -e "require('fs').mkdirSync('analysis',{recursive:true})"
ffmpeg -i "out/character-study.mp4" -vf "fps=4,scale=480:-2" "analysis/frame-%03d.png"
```

按时间顺序看抽出的图，记录具体时间，例如“第 2.0 秒左脚滑动”或“第 4.3 秒右手挡眼”。对问题点以更密集间隔或逐帧复查，再调整、重渲染、复看。除了角色，还需检查人物与字幕、真人画面、道具、边框和平台安全区之间的遮挡。若用户明确说“先看 10 秒样片”，交付可播放样片并等用户反馈；否则把样片当作内部质量检查，修好后继续完成用户要求的完整视频。
