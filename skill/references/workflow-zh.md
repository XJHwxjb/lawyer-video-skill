# 中文逐步执行指南：从口播素材到成片

本指南写给执行任务的 Agent。目标是交付用户要求的视频文件，而不仅是给方案、代码片段或 10 秒模板。每一阶段都要产生可检查的结果；遇到不能自行判断的关键事实，先完成不依赖该事实的部分，再向用户简洁说明缺少什么。

## 一、先读懂这次任务

1. 找出用户要的最终结果：完整成片、某一段样片，还是只修改现有视频。注意用户说的“先看样片”“其他不变”等限制。如果用户明确只要样片，做到样片就交付并等待反馈；如果用户要完整视频，10 秒样片只是内部检查步骤，不能当作完成。
2. 记录用户给的素材、输出位置、语言、比例、发布平台、时长、真人画面安排、风格和必须保留的内容。没有明确指定画幅时，结合已有素材和渠道选择合理方案，并在交付时说明假设；不要因为常规设计选择反复要求确认。用户的要求优先于本指南的示例。
3. 检查本机是否能读取文件并实际运行所需工具。不要把路径、文件名或工具版本当成所有用户的固定值。项目应保存在用户指定目录；输入文件只读，复制到新工程处理。未经授权，不把客户音视频、案件材料、人像或证据上传到公开仓库或外部服务。

**这一步应得到：** 一份素材清单、输出要求和可用工具记录；有不能打开的文件时记录具体路径与错误。

## 二、识别输入并建立可靠时间轴

| 已有素材 | 执行方法 | 需要特别注意 |
|---|---|---|
| 口播视频 + SRT | 检查视频与字幕时长；以 SRT 时间为起点，播放并逐句核对。 | 原视频画面和音轨来自同一段连续素材；不要再重复叠加一份同源音频。 |
| 口播视频 + 无时间的文字稿 | 提取或读取视频原声，用环境中可用的转写、字幕对齐工具建立带时间戳的逐句稿；对照用户稿与实际发言。 | 稿件不一定等于实际口播，不能把文字稿误当作已经有准确时间的字幕。 |
| 口播音频 + 头像 + 稿件/SRT | 保留原音频，以头像或其他经用户许可的形式呈现讲述者；将动作画面和字幕按音频时间对齐。 | 静态头像不是会说话的真人视频，不要声称做了口型驱动。 |
| 只有文字稿 | 用户若要求成片，先确认是否允许生成配音、使用什么声音；若无法取得授权或声音素材，则完成分镜等独立部分并说明缺口。 | 不要自行模仿特定真人的声音。 |

用 `ffprobe` 或同类工具检查媒体时长、分辨率、帧率、旋转信息与音轨；再实际试听/观看开头、中间和结尾。记录 `开始时间、结束时间、逐句文字`。如果 SRT 比视频早、晚或不完整，先检查素材是否来自同一版本；有明确证据时调整并记录，仍无法判断的关键差异应询问用户，不得自行猜测法律事实、案例、价格、金额或统计数字。用户给了 SRT 不代表它一定正确。

如果缺少转写工具，可以使用有权限的本地工具；若拟使用远程服务，先确认传输哪些素材、传给谁，并在获得授权后再执行。不能对齐时，说明没有完成并保留可编辑结果，不要伪称字幕已同步。

**这一步应得到：** 可校对的逐句时间轴，以及素材时长、音视频状态和未解决差异记录。

## 三、把口播逐句变成分镜

新建 `STORYBOARD.md` 或其他用户可读的分镜表。对完整口播从头到尾逐段处理，不要只设计开头。每一行至少包含：开始与结束时间、对应原句或句组、观众应理解的意思、出场人物和场景、实际动作与道具、字幕/真人的摆放、素材来源和转场方式。画面可使用原创人物、道具、时间线、简图和真实口播视频；必须能解释为何与该句口播对应。

例如，口播说“聊天记录和转账流水都要保存”，可分成“人物在手机上保留聊天记录 → 把转账凭证放入档案夹 → 两类材料并排对应”。这是把原句变成可见动作；它不是证据确实存在或某人一定犯罪的证明。不要加入原稿没有的涉案金额、身份、地点或结论。抽象规则可以用天平、证据链或对照线辅助，但不能整片只让文字逐条浮现。

制作长视频时，先按主题分段，再细化到逐句或短句组；同一场景内让人物行动、道具、视线或构图随语义发生变化。核查首句到末句每个时间段都被覆盖，镜头之间没有无意空白、重叠、漏句或字幕被头像遮挡。转账、持物等动作应与相关说话时间大致对应，避免过早暗示结果或与口播矛盾。

**这一步应得到：** 覆盖完整时长的分镜表；不确定的事实有标记，未被当作已确定内容写进画面。

## 四、创建工程并做人物动作检查

先复制 [人物动作测试模板](../assets/character-study/) 到独立项目，再按其中 README 安装、预览和渲染。模板是二维风格化人物和 10 秒示范，不是全自动成片程序；根据本次分镜改造人物、颜色、构图和动作，不能把测试文件直接当成客户成片。

先做短测试：包括自然站立、走路、停步、抬手、神情变化，以及本片确实会用到的持物动作。检查肩、肘、腕连接和弯曲方向，确认手指与道具有接触；走路时支撑脚应尽量不在地上滑动，身体起伏不要把落地脚一起抬起；查看人物是否突然翻转、手遮眼或不同人物机械同步。详细审查方式见 [人物动作设计与检查](character-animation.md)。

先做大画面关键帧，再实际播放一个完整动作周期和姿势切换；发现错误后修正并重渲，直到用户能看懂动作。真人视频默认使用真实录制画面与原声；如果采用圆形或侧边小窗，先检查头顶、下巴、手势和字幕安全区。用户要求先看样片时，给出样片并等待；否则继续处理整片。

**这一步应得到：** 独立工程、可播放短测试、动作检查记录及必要修正；真实客户素材不进入模板或公开仓库。

## 五、完成整片，不能停在模板

按照分镜依次创建覆盖完整口播时长的场景。始终以原声时间为主轴：原视频连同音轨连续播放一次；如需单独处理音频，静音视频中的声音，并确保处理后的音轨只播放一次且没有变速或漂移。字幕按其起止时间显示；如果是 SRT，不要无故改写原句。每个场景将人物、表情、行为、道具和简图与该段话的意思对齐。

采用 Remotion 时，逐步参考 [口播视频与 SRT 合成配方](remotion-assembly.md)：先准备副本和字幕数据，再接入连续播放的真人视频、独立字幕层和按时间启动的动画场景。配方里的角色只是示范，必须将其替换或扩展为分镜所需的实际内容；用户指定其他工具时，可用相同时间轴原则适配，不强制更换框架。

对原稿有口误、缺字、错别字或与实际发言不一致的地方，不默默修改法律含义。对重要数字、结论和案例事实先核对来源与口径。音乐和音效应有使用权限，音量不压过口播；可不加音乐。用户只要求修改某个局部时，保留其他部分，并只重新验收受影响部分和成片播放。

**这一步应得到：** 包含所有镜头、真人画面、字幕与音轨的可编辑项目，以及一份覆盖完整时长的成片 MP4。

## 六、验收后交付

对实际导出的 MP4 执行 [成片验收](delivery-qa.md)。至少核对文件可播放、时长与分辨率、原声音轨是否完整且未重叠、字幕和原稿及时间是否一致；看全片的关键帧与转场，并连续播放步行、停步、递物、表情变化等动作段。机器检测可辅助找黑帧、静音和时长错误，不能替代实际看与听。

交付时给用户可以点击或播放的成片路径和可编辑项目路径，说明时长、画幅、主要处理以及真正完成的检查。若缺少工具、无法访问素材、没有听看或某项质量仍未解决，具体说明限制；不要用“全部通过”掩盖未做的检查。
